Patent Response — Dentons Technical Questions

Hybrid Agentic & ML System for Requirement Quality Assessment

Inventor: Ali Reza Rashidi — Simple technical answers on agents, context extraction, and reuse detection

Closed-Loop Pipeline

Measure quality → detect gaps → clarify → rewrite → then run downstream engines.

Quality Gate

Primary Intent (What) must pass a quality and quantity threshold before search, estimation, or guidance.

Semantic Anchor + RAG

The enriched What anchors RAG retrieval over vectorized organizational memory.

Question 1

What distinct agents are involved, how do they coordinate, and what makes this different from a single monolithic ML model?

The system uses ten specialized agents, each with one job:

  1. Context Extraction Agent — collects requirement info from the story and permitted sources: description text, comments, links / URLs, attached images (OCR), Excel files, linked tickets; builds the Structured Context Package.
  2. Plainness Scorer — supervised ML (XGBoost) over readability features; scores English clarity.
  3. Deterministic LLM Evaluator — rubric-based; flags, extracts, and scores Who / What / Why / Acceptance Criteria.
  4. Scoring Engine — combines the Plainness Scorer and the Deterministic LLM Evaluator outputs into one 0–100 Quality Score (configurable weights).
  5. Clarification Agent — generates exactly four technical questions when the What has missing information.
  6. Rewriting Agent — human-in-the-loop; rewrites the story; the human keeps final control.
  7. Reuse Detection Agent — RAG (retrieval-augmented generation) over vectorized organizational memory: finds similar past stories and complementary delivery knowledge; runs only if the What passes the quality gate.
  8. Risk / Classification / Estimation Agent — classifies objective, value, customer impact; detects risks and dependencies; predicts story points.
  9. Developer Guidance Agent — writes a practical developer heads-up from organizational knowledge and previous similar work.
  10. Readiness Decision Agent — outputs Ready / Not Ready / Conditionally Ready / Needs Clarification.

Coordination

A quality-gated state machine, not a fixed chain. The What score is the master gate. Below threshold, downstream agents pause and control enters the loop: four questions → human answers → rewrite → re-evaluate. Above threshold, downstream agents run.

Difference from a monolithic ML model

  • No blind one-shot output: a monolithic model must answer everything from raw input, even vague input. This system improves the input first, then conditions all downstream output on measured quality.
  • Two separated LLM roles: a deterministic evaluator (scoring) and a controlled generator (questions, rewrite) — scores stay auditable.
  • Best-fit technique per sub-problem: XGBoost for plainness, deterministic LLM for semantics, RAG / vector search for similarity.
  • Human as a pipeline node: the human has final authority over the requirement.
  • Two separate verdicts: Quality Score (how well written) vs Developer Readiness (can work start) — one monolithic score cannot express both.
Question 2

What specific technical implementations are needed for agentic context extraction?

Extraction gathers everything the story already contains — in any form — and turns it into one structured package:

  1. Permission-aware connectors — authenticated adapters that read the story’s own artifacts: description text, comments, acceptance criteria, links / URLs inside the description, attachments, and linked tickets.
  2. Multi-modal parsing — OCR / vision for attached screenshots and diagrams; Excel and file parsing; link / URL resolution — because key information often lives outside the main description text (as a link, an image, or a file).
  3. Linked-artifact traversal — follow links and linked tickets to collect intent, constraints, and implementation details not stated in the description.
  4. Deterministic semantic extraction — a controlled LLM maps all collected inputs onto structured fields: What / Primary Intent, affected systems, business context, technical constraints, dependencies.
  5. Normalization — all signals become one machine-readable Structured Context Package, consumed consistently by every downstream agent.
Scope note: extraction only builds the complete context package. Gap analysis and the four clarification questions belong to the separate Clarification Engine downstream, and organizational-memory indexing belongs to the Reuse Detection Engine (Question 3).
Inventive point: extraction is not text preprocessing — it is a permission-aware, multi-modal reconstruction of the requirement’s true context from the story’s own scattered artifacts, and its output conditions every downstream decision.
Question 3

How is the reuse detection engine implemented?

  1. Quality gate (mandatory): check the quality and quantity of the What. Below threshold, no search — an ambiguous intent would return misleading matches. Control goes to the clarification loop instead.
  2. Semantic anchor: once the gate passes, the structured, enriched, rewritten What becomes the search query — not the raw story text.
  3. RAG search over organizational memory: the anchor is matched against the vector database of the whole organization’s data — completed tickets, implementation notes, comments, knowledge-base entries, standards and policy documents — with metadata filtering (system / team / category).
  4. Structured reuse extraction: from the top matches, extract: similar past stories, reusable implementation patterns, known risks and previous blockers, complementary delivery information (e.g., the latest API standards a developer would otherwise have to find and read manually), effort signals, and the teams / developers who previously did similar work.
  5. Downstream feeding: results feed (a) story-point estimation, (b) risk / dependency detection, (c) the developer heads-up.
Example: for “add a new API,” the engine retrieves and summarizes the organization’s latest API standards for the developer. It also finds a similar past story: these errors occurred during implementation, delivery took 10 days, difficulty was 10 (Fibonacci), and it was done by Team Z — the developers who did it are identified and can be contacted.
Net effect: historical knowledge becomes operational input — but only when the requirement is clear enough to match reliably. Gating + anchoring separates this engine from naive keyword or free-text search.
